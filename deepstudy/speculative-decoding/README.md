# Speculative Decoding · MTP — 깊이 보기

> 목적: LLM inference 시뮬레이터에 speculative decoding과 MTP를 넣기 위해
> **알고리즘을 연산 단위까지** 이해하고, **무엇을 어떤 모델로 구현할지** 정한다.
> 기준 시점은 2026년 10월이다. 계보 전체를 훑는 글은 [08-decoding](../../08-decoding.md)에 있고, 여기는 그중 실제로 쓰이는 것의 **작동 방식**을 깊게 판다.

## 모든 장이 같은 예시를 쓴다

프롬프트 **"The cat sat"** 뒤에 모델이 **"on"**을 막 만든 상황이다. drafter가 초안 `the mat and slept`를 내고, target은 `the mat` 다음에 `.`을 고른다. 그래서 초안 2개가 채택되고 `.`까지 **3개가 확정**된다.

그림의 색도 모든 장에서 같다.

| 색 | 뜻 | 예시에서 |
|---|---|---|
| 보라 | KV가 있는 확정 토큰 | `The cat sat` (프롬프트) |
| 점선 | 확정됐지만 KV가 아직 없는 토큰 | `on` — 다음 사이클에서는 `.` |
| 파랑 | 초안 | `the mat and slept` |
| 주황 | target이 그 자리에서 고른 토큰 | `the mat .` |
| 초록 | 채택된 초안 | `the mat` |
| 분홍 + 줄 | 버린 초안 | `and slept` |

그림은 [figures/](figures/)의 `make_figures.py`가 만든다 (`python make_figures.py`).

## 세 질문에 대한 짧은 답

**1) 표준이 되는 것이 있나?**

- **검증의 원리는 공통이다.** 초안을 target forward 한 번으로 확인하고, 출력 분포를 target 단독 샘플링과 같게 지킨다. 채택 알고리즘은 몇 갈래가 있고(토큰별 거부 샘플링, block verification, 트리), Medusa의 typical acceptance처럼 분포 일치를 포기하는 방식도 있다
- 채택 규칙은 **토큰별 거부 샘플링**이 기본이다. 검증 모양은 엔진 · 모델별로 일렬과 트리가 공존한다 — vLLM의 기본 경로와 SGLang의 새 엔진(Spec V2)은 일렬(`topk = 1`)만 받고, SGLang의 EAGLE 경로는 Llama · Grok 등에서 트리(기본 분기 4)를 쓴다
- **drafter는 하나로 정해지지 않았다.** "target의 hidden을 받아 쓰는 얇은 drafter"라는 부류가 주류가 됐고, 그 안에서 셋이 공존한다
  - **모델에 들어 있는 MTP** — 있으면 일단 이것을 쓴다. 따로 학습할 필요는 없지만, 추론 때 MTP 블록 · head 연산, 가중치 메모리, drafter KV가 든다
  - **EAGLE-3** — 사후 학습 drafter의 기존 표준. 공개 체크포인트가 가장 넓게 깔려 있다
  - **DFlash 계열 (DFlash → DSpark → DFlash 2)** — 2026년에 엔진 지원과 공개 체크포인트가 가장 빠르게 늘어난 쪽. 공개된 실험에서는 같은 target의 EAGLE-3와 내장 MTP보다 빨랐고, DeepSeek는 자체 서비스의 MTP를 DSpark로 바꿨다
- 근거는 엔진 지원 · 공개 체크포인트 · 공개 측정이다. 실제 서비스에서의 사용 비중을 보여 주는 자료는 없다

**2) draft/target 구도와 MTP 모듈, 무엇이 대세인가?**

- 독립된 작은 LLM을 draft로 두는 구도는 대형 서빙에서 **밀려났다.** 문맥을 처음부터 다시 읽고, target이 이해한 것을 쓰지 못하기 때문이다. 로컬(llama.cpp)과 특수한 경우에 남아 있다
- MTP 모듈 · EAGLE-3 · DFlash는 이름이 달라도 **같은 부류**다. target의 hidden("여기까지 읽은 이해")과 다음 토큰의 임베딩을 받아 얇은 층 몇 개를 돌린다. 갈리는 지점은 셋뿐이다
  - **언제 학습했나** — 본 학습과 함께(MTP) / 나중에 따로(EAGLE-3, DFlash)
  - **초안을 어떻게 뽑나** — 한 토큰씩(MTP, EAGLE-3) / 블록을 한 번에(DFlash 계열)
  - **target 정보를 어디로 받나** — 입력 한 곳(MTP, EAGLE-3) / 모든 층의 K · V(DFlash 계열) / target의 KV를 직접 읽기(Gemma 4)
- 흐름은 **"별도 모델 → 붙이는 얇은 모듈(순차) → 병렬 블록 + 부하에 맞춘 검증"** 이다. MTP는 "모델이 기본으로 주는 출발점"으로 남고, 공개 측정의 최전선은 병렬 블록 drafter로 넘어갔다

**3) 연산과 KV cache는?**

- verify는 decode와 같은 forward이고 **새 토큰 줄만 1 → K**가 된다. 가중치는 한 번 읽고, 곱셈과 KV 쓰기가 K배다. attention 곱셈은 `K·S`에 비례하고, 캐시를 몇 번 읽는지는 커널의 재사용 정도가 정한다
- target KV에 K줄을 쓰고 **맞은 만큼(a + 1줄)만 남긴다.** 롤백은 길이 값을 되돌리거나 자리를 반납하는 것이다
- drafter도 문맥을 읽어야 한다. **어디서 읽느냐가 drafter마다 다르다** — 자기 KV(1층 · 여러 층) / target의 KV / 없음
- MoE · 희소 attention · 선형 attention 혼합 모델에서는 "가중치는 한 번만 읽는다"와 "길이만 되돌리면 된다"가 **깨진다**
