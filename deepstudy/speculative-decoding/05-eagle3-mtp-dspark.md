# 05. EAGLE-3 · MTP · DSpark — drafter 자세히

> [구현 방안 페이지](../speculative-decoding-implementation.md)의 **3. Drafter**를 자세히 풀어 쓴 장이다. 같은 그림을 같은 순서로 따라가며, 그림의 각 부분이 무엇을 뜻하는지 설명한다.
>
> 이번 그림의 설정: **EAGLE-3 트리**(topk 2 · 깊이 3 · 예산 6) · **MTP-1** · **DSpark adaptive**(스케줄러 켬, 한가할 때).
> 예시: 프롬프트 `The cat sat` 뒤에 방금 확정된 토큰이 `on`이고, target은 그다음에 `the mat .`을 고른다.

|---|---|---|
| 1 | 갈래 지도 — 세 방법은 어디에 있나 | drafter 지도 |

| 3 | 한눈에 — 세 방법 비교 | 세 방법의 비교 |
| 4 | EAGLE-3 — 트리를 키우고, 예산만큼 검증한다 | EAGLE-3 |
| 5 | MTP — 본체 위에 붙은 블록 하나 | MTP |
| 6 | DSpark — 블록을 한 번에 뽑고, 요청마다 검증 길이를 고른다 | DSpark |
| 7 | 정리 — 시뮬레이터에 넣을 때 | — |
| 부록 | 엔진 설정 · 식 · 서비스 세부 | — |

## 1. 갈래 지도 — 세 방법은 어디에 있나

![drafter 지도](figures/05-drafter-map.png)

지도는 drafter를 **두 축**으로 나눈다.

| 축 | 갈래 | 뜻 |
|---|---|---|
| 어디에 사나 (세로) | 별도 모델 | 작은 LLM을 통째로 옆에 둔다. 자기 임베딩 · 자기 층 · 자기 KV |
| | **target에 붙는 얇은 모듈** | target의 hidden(여기까지 읽은 이해)과 출력 head를 받아 쓴다 — 층 몇 개로 충분하다 |
| | 모델 없음 | 지금까지의 토큰 열에서 같은 문자열을 찾아 온다 (n-gram · suffix) |
| 초안을 어떻게 뽑나 (가로) | 순차 | 초안 토큰마다 forward 한 번 (`γ`번) |
| | 병렬 | 블록 전체를 forward 한 번에 |

- **EAGLE-3 · MTP** — 얇은 모듈 · 순차. 2024 ~ 25년의 주류다
- **DSpark** — 얇은 모듈 · 병렬. DFlash 위에 두 가지를 더한 것으로, 2026년에 이쪽으로 옮겨 가는 흐름의 한 끝이다
- 셋 다 **target의 hidden을 받아 쓴다**(지도의 파란색). target이 이미 문맥을 읽었으니 drafter는 작아도 잘 맞힌다
- 별도 draft 모델과 모델 없는 방법은 이 장에서 다루지 않는다 ([02](02-drafters.md))

## 2. 모듈 모양 — 가운데 블록이 어떻게 생겼나

![drafter 모듈 셋](figures/43-drafter-modules.png)

세 모듈 모두 **입력 → 몸통(보라 점선) → head → 출력**으로 읽는다. 색은 셋 다 같다 — 노랑은 target에서 받는 hidden, 주황은 target 것을 그대로 함께 쓰는 부분(임베딩 · 출력 head), 파랑은 drafter 자신의 부분이다.

**EAGLE-3** — 얇은 층 하나를 초안마다 돌린다

| 부분 | 무엇을 하나 | 왜 |
|---|---|---|
| 입력 ① target hidden 3개 층 (`3d`) | target의 낮은 · 중간 · 높은 층 hidden을 이어 붙이고, 선형으로 `d`로 줄인다 | 마지막 층 하나보다 정보가 많다 — EAGLE-3가 더한 것 |
| 입력 ② 임베딩 | 직전에 뽑힌 토큰의 임베딩 (target 것을 함께 씀) | hidden은 "그 토큰을 고르기 전"의 상태라, 실제로 뭐가 뽑혔는지 알려 줘야 한다 |
| 이어 붙이기 → `2d` | 두 입력을 RMSNorm 뒤 이어 붙인다 | |
| **몸통: decoder layer × 1** | Q · K · V 투영이 `2d`를 바로 받는다. 자기 KV(1층분)를 가진다 | target이 문맥을 다 읽었으니 층 하나로 충분하다 |
| head: 자기 LM head (어휘 3.2만) | 자주 나오는 토큰만 가진 작은 head | drafter 한 스텝 비용에서 head가 큰 몫이라 줄였다 |
| 출력 | 다음 토큰 1칸의 분포 | 다음 칸은 **자기 hidden**을 target hidden 자리에 넣고 다시 돈다 |

**MTP (DeepSeek-V3)** — 모양은 EAGLE-3와 거의 같고, 세 가지가 다르다

| 부분 | EAGLE-3와 다른 점 |
|---|---|
| 입력 hidden | target **마지막 층 하나**의 hidden (`d`). 임베딩과 각자 RMSNorm → 이어 붙여 선형 `2d → d` |
| **몸통: Transformer 블록 × 1** | **본체 층과 같은 구조**(V3: MLA + MoE) — 그래서 무겁다. 모듈 하나가 14B |
| head | **target의 출력 head를 그대로** 쓴다 (어휘 전체) |
| 학습 | 따로 학습하지 않는다 — 본 학습 때 "그다음 토큰"을 맞히는 보조 손실로 함께 학습했다 |

**DSpark** — 층 3개를 한 번만 돌린다

| 부분 | 무엇을 하나 | 왜 |
|---|---|---|
| 입력 ① target 여러 층 hidden | 섞어서 **drafter의 층마다 K · V로** 넣는다 (KV injection, DFlash에서 물려받음) | 입력에 한 번 넣는 것보다, 어느 층에서든 target의 표현을 직접 읽게 한다 |
| 입력 ② 직전 토큰 + 빈칸 `γ`개 | 빈칸(마스크)을 포함한 블록을 target 임베딩으로 바꾼다 | 빈칸 `γ`개를 한꺼번에 채우려고 |
| **몸통: 블록 drafter × 3층** | 서비스용 MoE 3층. 최근 128토큰만 본다. **`γ`칸을 forward 한 번에** | 반복이 없으니 층을 쌓아도 사이클이 짧다 |
| head ① 출력 head (공유) | 칸마다 토큰 분포 | |
| head ② 보정 head | 왼쪽부터 칸마다, 직전에 뽑힌 토큰을 보고 다음 칸 점수를 고친다 (표 조회 + 작은 곱) | 빈칸을 동시에 채우면 "New Francisco" 같은 어긋난 조합이 나와서 |
| head ③ confidence head | 칸마다 "앞이 다 맞았다면 이 칸이 맞을 확률" | 몇 칸까지 검증할지 고르는 데 쓴다 (6절) |

**셋을 나란히 보면**

| | EAGLE-3 | MTP | DSpark |
|---|---|---|---|
| target에서 받는 hidden | 3개 층을 입력으로 | 마지막 층을 입력으로 | 여러 층을 층마다 K · V로 |
| 몸통 | decoder 1층 (얇음) | 본체와 같은 블록 1개 (무거움) | MoE 3층 |
| 초안 하나를 만드는 forward | 칸마다 1번 | 칸마다 1번 | 블록 전체에 1번 |
| head | 자기 작은 head | target head | target head + 보정 · confidence |
| 자기 KV | 1층분 × 문맥 | 1층분(MLA) × 문맥 | 3층분 × 최근 128토큰 |
| 학습 | 따로 (target은 얼려 둠) | 본 학습 때 함께 | 따로 |

## 3. 한눈에 — 세 방법 비교

![세 방법의 비교](figures/25-three-methods.png)

그림은 세 칸으로 읽는다 — **① 초안을 어떻게 만드나 → ② target에 얼마나 넣나 → ③ 시뮬레이터에서 다르게 셀 것.**

**① 초안을 어떻게 만드나**

- **EAGLE-3** — 얇은 drafter를 깊이마다 한 번 돌린다. 깊이 1에서 `on` 뒤에 상위 2개(`the`, `a`)를 붙이고, 깊이 2 · 3에서는 **지금까지 점수가 높은 노드 2개만** 골라 각자 상위 2개를 붙인다. 다 펼치면 후보가 10개 — 그중 점수 순으로 **6개만 남긴다**(예산)
- **MTP** — MTP 블록으로 한 개씩 만든다. MTP-1은 `the` 하나
- **DSpark** — 블록을 한 번에 계산해 5칸을 내고, 직전 토큰을 보고 가볍게 고친다. 칸마다 "여기까지 맞을 확률"도 낸다

**② target에 얼마나 넣나** — 언제나 "직전 확정 토큰 1줄 + 초안 줄"이다. 다른 것은 초안 줄의 수다. 그림의 주황 칸이 실제로 target에 들어가는 줄이다.

- **EAGLE-3** — 남긴 노드 6개 + 1 = **7줄**. 트리를 한 줄로 펴서 넣고, 각 노드가 자기 조상만 보게 가린다. 맞는 갈래를 따라 `the` ✓ `mat` ✓ 다음 답 `.`이 트리에 없어 멈춘다 → 확정 3 · 버림 4
- **MTP-1** — 초안 1 + 1 = **2줄**. `the` ✓ + 보너스 → 확정 2 · 버림 0
- **DSpark** — 5칸 중 스케줄러가 고른 앞 2칸 + 1 = **3줄**. 확정 3 · 버림 0. 몇 칸을 넣을지는 요청마다 · 스텝마다 다르다

**③ 시뮬레이터에서 다르게 셀 것**

| | 한 문장 |
|---|---|
| EAGLE-3 | 검증 줄(노드 수 + 1)과 최대 채택(깊이)을 따로 센다 |
| MTP | 초안을 늘리면 draft가 블록 수만큼 직렬로 길어진다 |
| DSpark | 생성 길이와 검증 길이를 따로 세고, 검증 길이는 스케줄러가 스텝마다 정한다 |

## 4. EAGLE-3 — 트리를 키우고, 예산만큼 검증한다

*이번 설정: 트리 (topk 2 · 깊이 3 · 예산 6)*

![EAGLE-3](figures/45-eagle-intuitive.png)

### 왼쪽 ① — 트리를 깊이마다 키운다

각 노드의 숫자는 **점수 = 뿌리부터 그 노드까지 확률의 곱**이다. 예를 들어 `the` → `mat`는 `the`의 0.60 × `mat`의 0.70 = 0.42다.

| 단계 | drafter가 하는 일 | 결과 |
|---|---|---|
| 깊이 1 | `on`에서 상위 2개를 낸다 | `the` 0.60 · `a` 0.25 |
| 깊이 2 | 점수 상위 2개(`the`, `a`)를 **한꺼번에** 넣어, 각자 상위 2개를 붙인다 | `mat` 0.42 · `floor` 0.12 · `mat` 0.125 · `big` 0.075 |
| 깊이 3 | 깊이 2에서 점수 상위 2개(`the mat` 0.42, `a mat` 0.125)만 펼친다 | `and` 0.21 · `with` 0.084 · `and` 0.05 · `.` 0.0375 |
| 예산으로 자르기 | 펼친 후보 10개를 점수 순으로 세워 **위에서 6개만** 남긴다 | 파랑 6개 남음, 회색 점선 4개 탈락 |

- drafter forward는 **깊이마다 1번**이다. 한 번에 펼칠 노드 2개를 함께 넣는다(첫 번은 직전에 확정된 줄을 넣는 갱신 패스)
- 자식의 점수는 항상 부모보다 낮다(확률을 곱하니까). 그래서 위에서 자르면 남은 노드가 저절로 트리 모양을 유지한다
- 깊이마다 "점수 상위 몇 개만 펼친다"가 `topk`, 마지막에 "몇 개를 남긴다"가 **예산**이다. 둘은 다른 손잡이다

### 오른쪽 ② — 7줄을 한 번에 넣고, 각 줄은 자기 조상만 본다

남긴 노드 6개와 직전 토큰 `on`을 한 줄로 펴서 target에 **forward 한 번**으로 넣는다. 일렬 초안과 다른 점은 attention을 가리는 모양이다.

- 표의 **행**은 질의하는 줄, **열**은 볼 수 있는 토큰이다. 칠한 칸 = 그 줄이 보는 토큰
- 예: `floor` 줄은 `on`, `the`, 자기 자신만 본다. 같은 깊이의 형제 `mat`는 보지 않는다 — 서로 다른 갈래이기 때문이다
- 그래서 형제 노드는 같은 위치(깊이)를 갖지만 서로 섞이지 않는다
- 초록 칸은 이번에 채택된 경로(`on → the → mat`)다

**채택** — 뿌리부터 target이 고른 토큰을 따라 내려간다.

| 자리 | target이 고른 것 | 트리에 있나 | 판정 |
|---|---|---|---|
| `on` 다음 | `the` | 있다 | ✓ |
| `the` 다음 | `mat` | 있다 | ✓ |
| `mat` 다음 | `.` | `mat`의 자식은 `and`뿐 | 멈춤 — `.`은 target의 토큰으로 확정 |

→ 확정 3개(`the mat .`), 버림 4줄(`a`, `floor`, `a`의 `mat`, `and`). 노드가 6개여도 **최대 확정은 깊이 + 1 = 4개**다.

**정리** — 채택된 경로의 KV는 펼친 줄 사이사이에 흩어져 있다. 그 KV를 연속 위치로 옮기거나(EAGLE 공식 구현) 자리 표를 고친다. 트리만의 일이다.

### 시뮬레이터에서

| 항목 | 세는 법 |
|---|---|
| draft | 깊이 `d`번 forward — 첫 번은 갱신 패스(직전 `a + 1`줄), 이후 `topk`줄씩 |
| verify | 예산 + 1줄, 모든 요청 같다. 트리 마스크 |
| 채택 | 최대 깊이 `d`개 + 1. 같은 트리 설정의 결과 분포를 쓴다 |
| 정리 | 채택 경로의 KV 옮기기 |

> 넓게 넣어 맞힐 기회를 늘리는 대신 많이 버린다. 남는 연산이 많은 작은 배치에서 유리하고, 배치가 크면 예산을 줄이거나 일렬(`topk = 1`)로 간다. 일렬이면 MTP와 같은 틀(초안 수 + 1줄)이 된다.

## 5. MTP — 본체 위에 붙은 블록 하나

*이번 설정: MTP-1 (DeepSeek-V3)*

![MTP](figures/46-mtp-intuitive.png)

### 왼쪽 · 가운데 — 본체와 MTP 모듈

- **본체(왼쪽)** 는 61층을 지나 출력 head로 다음 토큰 `on`을 낸다
- **MTP 모듈(가운데)** 은 본체가 `on`을 낼 때 쓴 hidden `h`(층 61의 출력)와 `on`의 임베딩을 받는다. 블록 1개와 출력 head를 거쳐 **그다음 토큰** `the`를 낸다 — 이것이 초안이다
- 블록은 **본체 층 1개와 같은 구조**(MLA + MoE)이고, 출력 head는 본체와 함께 쓴다
- 본 학습 때 "그다음 토큰"도 맞히도록 함께 학습한 모듈이라, 추론 때 그대로 drafter로 쓴다

### 오른쪽 — 한 사이클

| 단계 | 하는 일 |
|---|---|
| draft | MTP 블록 1번 + head → `the` |
| verify | target에 `on` · `the` **2줄** |
| 채택 | 결과는 둘 중 하나 — `the`가 맞으면 2개 확정(`the` + 보너스), 틀리면 1개(target의 토큰) |

📌 DeepSeek-V3에서 `the`가 맞을 확률(두 번째 토큰 채택률)은 85 ~ 90%다.

**초안을 3개로 늘리면** — 같은 블록을 직렬로 3번 돈다. 두 번째부터는 입력이 "자기가 낸 hidden + 방금 뽑은 토큰의 임베딩"이다. verify는 4줄. DeepSeek-V3는 MTP 모듈 하나로 학습했기 때문에, 반복해서 뽑는 뒤 칸은 학습 때 없던 쓰임이라 채택률이 빨리 떨어진다.

### 시뮬레이터에서

| 항목 | 세는 법 |
|---|---|
| draft | `γ` × (본체 층 1개 + 출력 head) — 직렬. MoE 블록이면 라우팅도 |
| verify | `γ + 1`줄, 모든 요청 같다 (MTP-1은 2줄) |
| 채택 | MTP-1이면 칸 1개 — `α` 0.85 ~ 0.90 |
| 메모리 | 블록 가중치(DeepSeek-V3 14B) + 1층분 KV(MLA) |

> draft 한 번이 가볍지 않다 — 배치 1에서 target 한 스텝의 약 4.4%. 대신 버리는 줄이 거의 없다.

## 6. DSpark — 블록을 한 번에 뽑고, 요청마다 검증 길이를 고른다

*이번 설정: adaptive (스케줄러 켬), 한가할 때, 요청 A · B · C*

![DSpark](figures/47-dspark-intuitive.png)

### ① 요청마다 5칸을 한 번에 + 칸마다 "여기까지 맞을 확률"

- drafter는 요청마다 블록 5칸을 **forward 한 번**에 낸다. 보정 head가 왼쪽부터 직전 토큰을 보고 다음 칸을 고친다
- confidence head가 칸마다 "앞이 다 맞았다면 이 칸이 맞을 확률" `c_k`를 낸다. 이것을 앞에서부터 곱한 것이 칸 안의 숫자 — **"여기까지 다 맞을 확률"**(생존 확률)이다
- 예: 요청 A는 0.95 → 0.85 → 0.51 → 0.18 → 0.04. C는 끝까지 높고, B는 첫 칸부터 불확실하다

### ② 배치의 모든 칸을 확률 순으로 세우고, 줄 예산까지 넣는다

- 요청 셋의 칸 15개를 확률 순으로 한 줄로 세운다
- 위에서부터 하나씩 넣으며 "기대 확정 수 × 처리 속도"를 계산하고, 그 값이 가장 클 때 멈춘다. 넣을수록 기대 확정 수는 늘지만 줄이 많아져 스텝이 느려지기 때문이다
- 이번에는 7칸(C1 · A1 · C2 · A2 · C3 · C4 · B1)에서 멈췄다 → 요청마다 직전 토큰 1줄을 더해 **10줄**
- 부하가 크면 줄 하나의 비용이 커져 선이 위로 올라간다(검증이 짧아진다)

### ③ 요청마다 다른 길이로 verify

| 요청 | 넣은 칸 | verify 줄 | 버린 칸 |
|---|---|---|---|
| A | A1 · A2 | 3 | A3 ~ A5 |
| B | B1 | 2 | B2 ~ B5 |
| C | C1 ~ C4 | 5 | C5 |

- 요청 안에서는 다른 방법과 같다 — 자기 초안의 **앞부분만** 넣고, 앞에서부터 비교한다. 다른 요청의 토큰과 섞이지 않는다
- 줄 수가 요청마다 다른(ragged) 배치다. 점선 칸은 검증하지 않고 버린다 — 틀릴 것 같은 칸에 verify 연산을 쓰지 않는다

**고정 `K`와 비교하면**

![고정 K와 DSpark](figures/32-fixed-vs-dspark.png)

- MTP · EAGLE 일렬은 요청마다 같은 줄 수를 넣는다(요청 수 × `K`)
- DSpark는 배치 전체의 줄을 맞을 확률이 높은 칸부터 나눈다. 다른 요청은 **몇 칸을 넣을지 정할 때만** 영향을 준다

**서비스에서는** — CUDA graph 때문에 다음 스텝의 총 줄 수를 미리 알아야 한다. 그래서 총 줄 수는 **2스텝 전의 confidence**로 정하고, 요청별 배분은 이번 confidence로 정한다.

📌 DeepSeek-V4 서비스에서 MTP-1(요청당 2줄 고정) 대비, 같은 처리량에서 사용자당 생성 속도 V4-Flash +60 ~ 85%, V4-Pro +57 ~ 78%. 중간 부하에서 요청당 약 4 ~ 6줄을 검증했다.

### 시뮬레이터에서

| 항목 | 세는 법 |
|---|---|
| draft | 갱신(새 문맥 `a + 1`줄 투영) + 블록 1번(`γ + 1`줄) + 보정 `γ`칸 — 생성 길이는 늘 5칸 |
| verify | 요청마다 `ℓ_r + 1`줄 — 스케줄러가 스텝마다 정한다 |
| 채택 | 자리별 `α`로 판정. confidence는 고르는 데만 쓰고 채택 확률과 따로 둔다 |
| 메모리 | 3층 × 최근 128토큰 KV — 문맥 길이와 무관 |

## 7. 정리 — 시뮬레이터에 넣을 때

| | draft 비용 (스텝당) | verify 줄 | 최대 채택 | 따로 둘 것 |
|---|---|---|---|---|
| EAGLE-3 트리 | 갱신 패스 + (깊이 − 1) × `topk`줄 | 예산 + 1 | 깊이 `d` | 트리 마스크 · 채택 경로 정리 |
| EAGLE-3 일렬 | 갱신 패스 + (`γ` − 1) × 1줄 | `γ + 1` | `γ` | — |
| MTP | 갱신 패스 + (`γ` − 1) × 블록 | `γ + 1` (MTP-1은 2) | `γ` | — |
| DSpark | 투영 + 블록 1번 + 보정 | 요청마다 `ℓ_r + 1` | `ℓ_r` | 스케줄러 · 2스텝 전 confidence |

- 갱신 패스 · 투영 = 직전에 확정된 `a + 1`줄을 진짜 hidden으로 drafter에 넣는 패스. 줄 수가 직전 채택에 따라 바뀐다 → [06의 3번](06-sim-realism.md#3-draft-비용--drafter가-초안을-만드는-시간)
- 채택 모형은 셋 다 같은 틀이고 `α` 곡선 모양만 다르다 → [06의 1번](06-sim-realism.md#1-채택-모형--초안-중-몇-개가-맞나)

<details>
<summary>EAGLE — 예산으로 자르는 과정과 엔진 매개변수</summary>

![EAGLE의 트리 초안과 예산](figures/26-eagle-tree-budget.png)

| 손잡이 | 뜻 | SGLang | Llama 기본 | 다른 모델 기본 | EAGLE 논문 |
|---|---|---|---|---|---|
| 깊이 `d` | 최대 채택 길이 | `--speculative-num-steps` | 5 | 3 | 6 (EAGLE-3 8) |
| `topk` | 깊이마다 펼치는 갈래 | `--speculative-eagle-topk` | 4 | 1 | 10 |
| 예산 | target이 검증하는 줄 수 | `--speculative-num-draft-tokens` | 8 | 4 | 노드 60개 안팎 |

- SGLang의 `num-draft-tokens`는 뿌리를 포함한 `K`다. `topk = 1`이면 일렬이 되고 `K = 깊이 + 1`로 맞춰진다
- SGLang의 새 엔진(Spec V2)과 vLLM의 기본 경로는 일렬만 받는다
- 샘플링(temperature > 0)이면 한 자리의 형제 후보를 차례로 시도하는 거부 샘플링을 쓴다. 시뮬레이터에서는 같은 설정의 결과 분포를 쓰는 편이 간단하다
- EAGLE-2(2024)의 동적 트리를 EAGLE-3(2025)가 이어 쓴다. Llama-3.1-8B용 EAGLE-3: 층 1개, `d` 4096, FFN 14336, 어휘 3.2만

</details>

<details>
<summary>MTP — 식 · 비용 · 변형</summary>

![MTP의 초안 만들기](figures/41-mtp-chain.png)

```
h'_i  =  M · [ RMSNorm(h_i) ; RMSNorm(Emb(t_(i+1))) ]          M : 2d → d
h''_i =  TRM( h'_i )                                            본체와 같은 Transformer 블록 하나
P(t_(i+2)) = OutHead( h''_i )                                    본체의 출력 head를 함께 쓴다
```

- `γ` > 1: vLLM · SGLang 모두 같은 블록을 반복한다. vLLM-Ascend 문서는 DeepSeek MTP로 3개 이상은 보장하지 않는다고 적는다. FastMTP는 반복용으로 미세조정한다. Qwen3.5 비교(SGLang 블로그)는 7스텝으로 돌렸다
- SGLang에서는 MTP도 EAGLE 경로를 타므로 `topk` > 1로 트리를 만들 수도 있다
- MTP를 가진 공개 모델: DeepSeek-V3 · V3.2 · V4, Qwen3-Next · Qwen3.5 · Qwen3.6, GLM-4.5 · GLM-5.x 등

</details>

<details>
<summary>DSpark — 검증 길이를 고르는 식</summary>

![DSpark의 검증 길이 고르기](figures/27-dspark-schedule.png)

```
보정:        로짓_k += W1[x_(k−1)] · W2                 W1 : V × r,  W2 : r × V,  r = 256
confidence:  c_k = σ( wᵀ [ h_k ; W1[x_(k−1)] ] )        학습 목표 c_k* = 1 − ½ ‖p_draft − p_target‖₁
생존 확률:   a_(r,j) = c_(r,1) × … × c_(r,j)
배치 줄 수:  B = Σ_r (1 + ℓ_r)
기대 확정:   τ = Σ_r (1 + Σ_(j ≤ ℓ_r) a_(r,j))
목표:        Θ = τ · SPS(B)        SPS(B)는 엔진을 켤 때 한 번 재 둔 표 (줄 수 B에서 초당 스텝 수)
```

- 그림 27의 SPS는 설명용으로 가정한 비용 곡선이다 (줄 하나에 스텝 시간 +10% · +20%)
- confidence 보정은 왼쪽부터 칸마다 온도를 하나씩 맞추는 방식(Sequential Temperature Scaling)이다. 보정 오차(ECE)를 3 ~ 8%에서 약 1%로 줄였다
- 오프라인 실험(초안 7개, 5층 drafter, 스케줄러 끔)의 `τ`: Qwen3-4B GSM8K EAGLE-3 5.14 · DFlash 5.40 · DSpark 6.11
- vLLM의 "Adaptive Verification"이 이 검증 길이 조절이고, 현재 DSpark만 지원한다

</details>

<details>
<summary>자세한 비교 표</summary>

| 단계 | EAGLE-3 | MTP | DSpark |
|---|---|---|---|
| drafter | decoder 1층 + 작은 head (어휘 3.2만) | 본체와 같은 블록 1개 + target head | MoE 3층 (서비스용) + 보정 head + confidence head |
| drafter forward | 깊이 `d`번 — 첫 번은 직전에 확정된 `a + 1`줄, 이후 `topk`줄 | `γ`번 (MTP-1은 1번) — 첫 번은 `a + 1`줄 | 새 문맥 `a + 1`줄 투영 + 블록 1번 + 칸마다 아주 싼 보정 |
| 만드는 후보 | `topk + (d − 1) · topk²`개 → 예산 `N`개만 남김 | `γ`개 | `γ`개 (서비스 최대 5) → 앞 `ℓ_r`개만 검증 |
| 초안 모양 | 트리 | 일렬 | 일렬 + 칸별 통과 확률 |
| verify 줄 `K` | `N + 1` — 모든 요청 같다 | `γ + 1` — 모든 요청 같다 | `ℓ_r + 1` — 요청 · 스텝마다 다르다 |
| attention 가림 | 조상만 보는 트리 마스크 | 계단 | 계단 (요청마다 길이가 다르다) |
| 채택 | 뿌리부터 맞는 갈래를 따라간다 | 앞에서부터 | 앞에서부터 |
| 최대 확정 | 깊이 + 1 | `γ + 1` | `ℓ_r + 1` |
| 버리는 줄 | `N − a` | `γ − a` | `ℓ_r − a` |
| 길이를 정하는 것 | 설정값 (깊이 · topk · 예산) | 설정값 (`γ`) | 스케줄러 (confidence + 부하) |

</details>
